# Changelog

All notable changes to Pretend Terminal are documented here. Package-specific
release notes are generated by [Changesets](https://github.com/changesets/changesets)
when a release is prepared.

The project has not been published yet. The first public release will be
`0.1.0`.

## Release-note convention

- Write a Changeset for every consumer-visible change to
  `@pretend-terminal/core` or `@pretend-terminal/react`.
- Use the smallest semver bump that accurately describes the public API
  impact: `patch` for compatible fixes, `minor` for compatible features, and
  `major` for breaking changes.
- Keep the summary focused on what a consumer can observe or needs to do; link
  to relevant issues or pull requests when available.
- Do not create a Changeset for internal-only tooling, test, or documentation
  changes unless they affect a published package.
- Before publishing, run the full validation suite, apply Changesets, review
  the generated package changelogs and manifest versions, then have the
  repository owner explicitly approve the publish command.
